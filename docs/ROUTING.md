# Маршрутизация, обход DPI и Telegram

Как в Hydra (0.7.13–0.7.15) устроены правила «что → через какой выход», обход DPI без сервера (ByeDPI), подбор стратегий,
Telegram по WebSocket и geo-базы. Для пользователя — раздел «Маршрутизация»; для разработчика — карта кода внизу.

## Где это в интерфейсе

| Платформа | Путь | Вкладки |
|---|---|---|
| Android | Настройки → **Маршрутизация** | Приложения · Сайты и IP · Обход DPI · Выходы |
| Android | Настройки → **DNS, гео и профили** | DNS, страны (geoip), фрагментация, MTU, IPv6, профили маршрутизации |
| Android | Настройки → **Geo-базы** | источники, расписание, статус, откат, свои списки |
| ПК (Compose) | **Маршруты** | Программы · Сайты и IP · Обход DPI · Выходы · Страны и профили (в ней же geo-базы) |
| Hydra Classic (Swing) | Маршруты | те же разделы одним экраном (`RoutingPanel`, `DpiPanel`) |
| iOS | Настройки → «Обход DPI и выходы», «Geo-базы» | вкладки, настройки подбора, TG WS и кнопка Telegram - с 0.7.20 |

Вопросы вкладок: **Приложения/Программы** — кто идёт через VPN (режим «все / только выбранные / все, кроме выбранных») и
свой выход для приложения; **Сайты и IP** — то же по доменам и диапазонам IP плюс правила «условие → выход»; **Обход DPI** — мастер
подбора, движок ByeDPI, настройки подбора, Telegram по WebSocket, кнопка «Подключить Telegram к прокси»; **Выходы** — группы
выходов и цепочки серверов.

## Выходы и правила

**Выход** — тег sing-box, куда уходит трафик:

| Выход | Тег | Что это |
|---|---|---|
| VPN | `proxy` | основной сервер |
| Напрямую | `direct` | мимо VPN (опция «через обход DPI» — см. ниже) |
| Обход DPI | `dpi` | локальный SOCKS5 ByeDPI, порт 10880 |
| Telegram по WebSocket | `tgws` | локальный SOCKS5 TG WS, порт 10881 (MTProto-прокси того же TG WS - порт 10870) |
| Блок | — | `action: reject` |
| Любой сервер из списка | `node-<id>` | у OpenFlux и olcRTC — свой клиент-подпроцесс на свободном порту |
| Группа | `grp-<имя>` | `urltest` («авто»: самый быстрый живой, с переключением при сбое) или `selector` («ручной») |

**Правило** — условие + выход. Условия: приложение (Android) / программа (ПК), домен, суффикс, слово, regex, диапазон IP, IP клиента,
порт или диапазон, протокол (sniff: tls/http/quic/…), сеть tcp/udp, страна (IP) и набор доменов (geoip/geosite). Условия с одной
меткой склеиваются по «И», «НЕ» инвертирует. Правила проверяются сверху вниз; первое подходящее выигрывает.

**Цепочки** («протокол внутри протокола») любой глубины: любой TCP-сервер (VLESS/VMess/Trojan/Shadowsocks) пускается через обход DPI
или через другой сервер (`detour`); петли и UDP-протоколы отсекаются предупреждением в журнале.

Конфиг sing-box строится как раньше, а план накладывается на готовый JSON одной функцией — `RoutePlanApplier.apply`
(`shared/.../data/routing/RoutePlan.kt`; копия для Android лежит в `app/`, порт на Swift — `Routing.swift`). Правила вставляются сразу
после `sniff` и `hijack-dns`. Если подпроцесс (ByeDPI, TG WS) не запустился, `withoutDpi()` / `withoutTgWs()` убирают всё, что на него
опирается, — соединение поднимается без него, причина в журнале.

## Обход DPI (ByeDPI)

Движок — `ciadpi` (hufrea/byedpi, MIT): локальный SOCKS5, который режет и подделывает первые пакеты соединения. Это не VPN: IP он
не скрывает. Три режима: профиль **«Обход DPI»** (tun/прокси → ByeDPI → интернет напрямую; ссылка `byedpi://?s=…`), трафик
**«напрямую» через ByeDPI** (правила «мимо VPN», страны «напрямую») и выход **`dpi`** в правилах, группах и цепочках.

### Мастер подбора

Как «проверка прокси» в [ByeByeDPI](https://github.com/romanvht/ByeByeDPI), но с понятным итогом «открылось 11 из 12»:

1. отметить списки доменов (и при желании свой сайт);
2. сначала проверка **без обхода** — если всё открывается, обход не нужен;
3. перебор: «быстро» — первые 15 стратегий, «тщательно» — все 60 (или **свой список**); остановка на первой, открывающей всё;
4. три лучших с кнопками «Использовать», «Сохранить профилем», «Копировать»; кнопка «Показать все результаты (N)» раскрывает весь
   перебор. Строка стратегии показывается и копируется **целиком**.

### Настройки подбора (0.7.15)

Те же, что в ByeByeDPI, но с пояснением под каждой (`DpiProbeSettings`, хранится в `RouteConfig.dpi.probe`):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| Ожидание между проверками | 1 с | пауза между стратегиями; больше — стабильнее на слабой сети |
| Количество запросов к домену | 1 | сайт открыт, если ответило **большинство** попыток |
| Максимум параллельных запросов | 16 | больше — быстрее, но менее стабильно |
| Таймаут ответа домена | 4 с | больше — медленнее, но точнее |
| SNI фейк-пакетов | `max.ru` | подставляется вместо `{sni}` в стратегиях — и при подборе, и в обычной работе |
| Списки доменов | YouTube, Discord, Telegram | Cloudflare, Discord, Общие, Googlevideo, Соцсети, Telegram, Türkiye, YouTube + **свои** |
| Свой список стратегий | выкл | по одной в строке, `#` — комментарий; пока включено, встроенные 60 не проверяются |

60 готовых стратегий и сайты проверки — из ByeByeDPI (GPL-3.0, как Hydra), см. `THIRD_PARTY_NOTICES.md`.

## Telegram по WebSocket (TG WS, 0.7.14)

Когда Telegram не открывается даже через ByeDPI. Собственная реализация на Kotlin (`shared/.../data/tgws/TgWsProxy.kt`). Как работает:

1. локальный SOCKS5 на `127.0.0.1:10881`; соединения к подсетям Telegram (`149.154.160.0/20`, `91.108.0.0/16`, `91.105.192.0/23`,
   `185.76.151.0/24`, `95.161.64.0/20`) обрабатываются, остальные проходят напрямую;
2. номер ЦОД читается из 64-байтового «obfuscated init» клиента (AES-256-CTR: ключ `init[8..40)`, IV `init[40..56)`; тег протокола и номер
   ЦОД в байтах 56..64); у мобильных клиентов без секрета номер берётся по адресу и дописывается в init;
3. вместо TCP поднимается **WebSocket поверх TLS 1.2** до `kws<N>.web.telegram.org/apiws` (подпротокол `binary`; для медиа сначала
   `kws<N>-1`); адрес берётся из DNS домена, запасной — из таблицы (у части провайдеров отдельные адреса ЦОД блокируются глухо);
4. склеенные клиентом MTProto-сообщения режутся по кадрам (реле разбирает по одному сообщению на кадр);
5. редирект или сбой WebSocket → откат на прямой TCP; ЦОД, отвечающий редиректом, заносится в чёрный список на сеанс.

Включается пресетом «Telegram → WebSocket» (правила `ip_cidr` подсетей → выход `tgws`), мастер подбора сам предлагает его, если Telegram
не открылся ни с одной стратегией. Android, ПК (обычная Hydra и Classic) и iOS (с 0.7.20, внутри расширения VPN). Проверено: ответ ЦОД Telegram через прокси
(`TgWsLiveTest`, `HYDRA_LIVE_TGWS=1`) и юнит-тесты разбора; полноценная сессия Telegram на телефоне — не проверялась.

**Режимы клиента Telegram (0.7.20).** По SOCKS5 клиент Telegram для Android не обфусцирует поток (шлёт `0xEF` + MTProto открытым текстом), а при IPv6 использует
адреса ЦОД по IPv6: TG WS распознаёт первый байт (обфусцированный init или открытый транспорт `0xEF` / `0xEEEEEEEE` / `0xDDDDDDDD`), по адресу (в т. ч. IPv6)
определяет ЦОД, строит собственный obfuscated2 до ретранслятора и перешифровывает поток. **MTProto-прокси** (`tg://proxy`, порт 10870, секрет `dd`+16 байт) -
клиент шлёт init, ключ которого SHA-256(init[8..40) + секрет); так Telegram подключается без сбоев и на Android. Секрет постоянный (слушатель только на 127.0.0.1).

### «Подключить Telegram к прокси» (0.7.15)

Кнопка в настройках обхода и на главном экране (когда подключено и есть локальный прокси) открывает
`tg://proxy?server=127.0.0.1&port=10870&secret=dd…` (MTProto-прокси TG WS), если пресет «Telegram → WebSocket» включён, иначе `tg://socks?server=127.0.0.1&port=<порт>`
(SOCKS5); Telegram спросит, включить ли прокси. Порт SOCKS5 — ByeDPI (10880; у профиля «Обход DPI» — порт профиля). **Прокси работает, пока Hydra подключена**; без Telegram Android показывает
«Telegram не установлен».

## Geo-базы (0.7.13)

`geoip`/`geosite` (`.srs` sing-box) — динамический слой поверх вшитых: источники MetaCubeX, SagerNet, runetfreedom (в т. ч. наборы
`ru-blocked`), v2fly и runetfreedom в формате `.dat` (нужные записи конвертируются на устройстве), свои списки по ссылке (CIDR/домены,
`.srs`, запись из `.dat`); зеркала; автообновление (6 ч – 7 дней); проверка формата, версии и размера, атомарная замена, откат,
статус и SHA-256 каждой базы. Скачанное приоритетнее вшитого. Пресет **«Заблокированное в РФ → обход DPI»** (`geosite`/`geoip`
`ru-blocked` → `dpi`) включает всё одной кнопкой.

## Ограничения

- iOS: TG WS, вкладки и настройки подбора появились в 0.7.20 и проверены сборкой в CI, на устройстве — нет.
- Выход `tgws` работает только на TCP-подсетях Telegram; звонки (UDP) идут как обычно.
- Подбор на включённом VPN идёт через VPN — для честного результата отключитесь (на ПК в режиме TUN мастер предупреждает).
- Значок на панели задач Windows, закреплённый пользователем, хранит Проводник: после смены значка его нужно открепить и закрепить заново.
