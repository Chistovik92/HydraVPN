## Решение владельца (11.10.2026): для 3x-ui — API-токен

Вход в API 3x-ui — **Bearer-токеном**, а не cookie-сессией (`POST /login`). Сверено с апстримом 3x-ui v3.9.0:

- токен выдаёт сам установщик: `/etc/x-ui/install-result.env` содержит `XUI_API_TOKEN` (рядом `XUI_USERNAME`, `XUI_PASSWORD`, `XUI_PANEL_PORT`,
  `XUI_WEB_BASE_PATH`, `XUI_ACCESS_URL`, `XUI_DB_TYPE`); для уже стоящей панели — `x-ui setting -getApiToken` по SSH;
- `Authorization: Bearer <token>` работает для всех `/panel/api/*`, CSRF-токен не нужен;
- токен лежит как секрет (в памяти сеанса; «запомнить» — Keystore/шифрованный файл, как в 0.8.0), в журнал не попадает.

Нужные методы (`docs/content/docs/en/reference/api` апстрима, `docs/public/openapi.json`):

| Что | Метод |
|---|---|
| Проверка токена, версия | `GET /panel/api/setting/all` |
| Инбаунды | `GET /panel/api/inbounds/list/slim`, `POST /panel/api/inbounds/add` |
| Клиент в инбаунде(ах) | `POST /panel/api/clients/add` (`{client:{email,subId,totalGB,expiryTime,limitIp,…}, inboundIds:[…]}`) |
| Ссылки клиента | `GET /panel/api/clients/links/{email}` — готовые `vless://…`, импортируются в «Серверы» **без** сервера подписки |
| Ссылки по subId | `GET /panel/api/clients/subLinks/{subId}` |
| Адрес подписки | настройки панели (`subPath`, порт) + `{subPath}{subId}` |

s-ui и x-ui (alireza0): токена нет — вход `POST /api/login` / `POST /login`, cookie сессии, пароль по умолчанию `admin/admin` **меняем сразу**.

## Условия выпуска

Юнит-тесты A–E, живой прогон 3x-ui в WSL (установка → токен → клиент → ссылки → импорт), `sing-box check` импортированных конфигов, сборки Android и ПК; проверка на VPS владельца остаётся отметкой «не проверено на сервере», пока не сделана.

## Принципы

Те же, что в 0.8.0: команды видны до запуска, скрипты закреплённых тегов, ничего наружу без согласия, пароли и токены не пишутся в журнал.
