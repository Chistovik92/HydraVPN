# План 0.7.14 — единая «Маршрутизация», Telegram по WebSocket, значки на ПК

Запрос владельца 10.10.2026 (выпущено в тот же день). Описание устройства — [`../ROUTING.md`](../ROUTING.md).

## Задачи и результат

| № | Задача | Результат |
|---|---|---|
| 1 | Стратегии ByeDPI не прокручивались | выбор в окне с прокруткой (`PickerDialog` / `PickDialog`), 60 строк |
| 2 | Группы выходов и правила настраивать выпадающими списками | `DropdownField` / `DropField`: режим, условие, выход, тип группы, «через» в цепочках; состав группы — галочки в окне |
| 3 | Пересмотреть «Маршрутизацию», «Split-туннелинг» и «Обход DPI» | один раздел с вкладками: Android — Приложения · Сайты и IP · Обход DPI · Выходы; ПК — + Страны и профили |
| 4 | Значок на Windows и Linux | выбор с миниатюрами вверху «Настроек»; обновление ярлыков Windows (`.lnk` на рабочем столе и в «Пуске»), `.desktop` Linux, Dock macOS (`LauncherIcon`) |
| 5 | Telegram, если не подбирается через ByeDPI — tg-ws-proxy и похожие проекты | TG WS: собственная реализация на Kotlin, выход `tgws`, пресет «Telegram → WebSocket», подсказка в мастере; Android и ПК |
| 6 | Серверы: после неудачного пинга — красное «недоступно» (не кнопка) | `PingMeasurer.UNREACHABLE = -2`, подпись без нажатия |
| 7 | Смотреть интерфейс на эмуляторах | эмулятор Android (hydra35) и окно Windows — снимки до и после |

## Критерии готовности и что проверено

- Юнит-тесты ПК (`TgWsProxyTest`, 8): номер ЦОД из init, разрезание сообщений, SOCKS-проход, правило в плане sing-box.
- Живой тест `TgWsLiveTest` (`HYDRA_LIVE_TGWS=1`): WebSocket до серверов Telegram через прокси поднимается (TLS 1.2; адрес из DNS домена).
- Не проверено: сессия Telegram на телефоне; обновление ярлыков на чистой установке; iOS (интерфейс остался как в 0.7.13).

## Источники идей

Код собственный: локальный SOCKS5 на 127.0.0.1, WebSocket на ЦОД Telegram.
