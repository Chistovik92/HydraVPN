# План Hydra 0.7.11

Статус: **согласован владельцем** (09.10.2026). Версия идёт после 0.7.10 и до 0.7.12 (обход DPI, маршрутизация через
несколько протоколов) — см. [ROADMAP.md](../ROADMAP.md). Каждый блок ниже — отдельный PR; релиз всех платформ одним
`scripts/release.sh`, когда готовы все блоки или владелец решит выпускать без отложенных.

## Цели

1. **OpenFlux как в официальных клиентах** — учесть [OpenFluxAndroid](https://github.com/p1neappleXpress/OpenFluxAndroid)
   и [OpenFluxDesktop](https://github.com/p1neappleXpress/OpenFluxDesktop) (v2.3.2, ядро OpenFlux 0.4.2): свежее ядро,
   официальные ссылки `openflux://v1/`, сессии из нескольких транспортов с автопереключением, прохождение проверки
   (SmartCaptcha) во встроенном браузере.
2. **Тестирование iOS через TestFlight** — подробная инструкция ([IOS_TESTING.md](../IOS_TESTING.md)) и подготовка CI к
   выгрузке сборок, когда появится аккаунт Apple Developer; бета OpenFlux в TestFlight
   (<https://testflight.apple.com/join/BwnAcdus>) — эталонный клиент для проверки узлов и ссылок на iPhone.
3. **Скорость в моменте** (запрос 09.10.2026) — главный экран, шторка, трей.
4. **Идеи Meridian и остатки устойчивости** (план 0.7.9 → 0.7.11): пресет «Российские приложения напрямую», запасной
   источник обновлений, отмена подключения, хвост 7a.

## Блок A. Ядро OpenFlux 0.4.2 на всех платформах

- Коммит ядра `bb55dc3` → `74cac6d` (метка v0.4.2): `desktop/build.gradle.kts` (готовые бинари + SHA-256 из `SHA256SUMS`
  релиза, Classic собирает из коммита), `scripts/build-openflux.sh` (Android), `ios/Bridge` (замена клона и `go.sum`),
  `scripts/check-updates.sh` — сверка с апстримом и для OpenFlux-клиентов (v2.3.x) как источника изменений.
- Проверить, что флаги CLI (`--transports`, `--direct-dial`, `--encryption-key-file`, `--negotiate`) не изменились:
  `OpenFluxLiveTest`, e2e `desktop-e2e.sh` (OpenFlux на трёх ОС), эмулятор Android с exit-узлом на хосте.
- Готовность: все три проверки зелёные; в CHANGELOG — какие исправления ядра получили пользователи.

## Блок B. Официальные ссылки `openflux://v1/`

- **Импорт везде:** ссылку разбирает само ядро, как требует апстрим. ПК и Android — подпроцесс `openflux --parse-link -`
  (ссылка через stdin, ответ JSON `{"config","context"}` или `{"error","code","param"}`); iOS — функция в `hydraflux`
  поверх пакета `share` ядра. Коды ошибок (`damaged`, `short_secret`, `unknown_transport`, …) — свои понятные тексты на
  5 языках, не английский текст ядра.
- **Хранение:** профиль OpenFlux получает поле «сессия» (JSON списка транспортов + контекст + кодек + режим), ключ — в
  `uuidOrPassword` как сейчас. Старые профили Hydra (`openflux://direct?url=…`) читаются как раньше и превращаются в сессию
  из одного транспорта.
- **Экспорт и QR:** «Поделиться» для OpenFlux строит ссылку через ядро (`--make-link`), чтобы она совпадала со ссылкой
  официальных клиентов; старая ссылка Hydra больше не создаётся (только читается).
- **Режим `stream`** (узел «без сервера» на PHP-хостинге): распознаём и честно сообщаем «пока не поддерживается» — его
  клиентская часть другая (`StartStreamProxy`), берём в 0.8.0 вместе с мастером узла.
- Готовность: ссылка, сделанная OpenFluxAndroid/Desktop, импортируется в Hydra на Android, ПК, iOS и подключается; ссылка
  из Hydra открывается в официальных клиентах и в бете из TestFlight; тесты на «замороженных» ссылках из
  `share/compat_test.go` ядра.

## Блок C. Сессии из нескольких транспортов

- Запуск клиента с `--negotiate --transports=direct:100,yandex:50 …` и ссылками на документ для каждого типа
  (`--yandex-url`, `--mailru-url`, …); на iOS — `StartSessionProxy(specsJSON, key, …)`.
- Карточка сервера: список транспортов с приоритетами и состоянием («активен», «ждёт проверки», «нет связи»), какой
  транспорт сейчас несёт трафик — из журнала/IPC ядра.
- Готовность: e2e на ПК с двумя транспортами (`direct` + второй `direct` на другом порту) — обрыв первого переключает на
  второй без переподключения туннеля.

## Блок D. Проверка транспорта (SmartCaptcha, вход)

- Яндекс (и MAX/Mail.ru при входе) иногда требуют пройти проверку в браузере; ядро ждёт cookies. В официальных клиентах —
  встроенный браузер. В Hydra: Android — WebView-экран, iOS — WKWebView в приложении (расширение VPN передаёт запрос через
  App Group), ПК — окно браузера по умолчанию с локальным прокси ядра и передачей cookies обратно по IPC ядра
  (`transport/ipc`); Classic — то же через системный браузер.
- Уведомление «OpenFlux ждёт проверку» с кнопкой «Пройти» в шторке/трее.
- Готовность: сценарий проверяется на настоящем документе Яндекса владельца; без него — юнит-тест передачи cookies на
  поддельном транспорте (`ipc_e2e_test.go` ядра — образец).

## Блок E. Тестирование iOS через TestFlight

- [docs/IOS_TESTING.md](../IOS_TESTING.md): установка беты OpenFlux из TestFlight и сверка с Hydra; как завести TestFlight
  для Hydra (аккаунт Apple Developer, идентификаторы приложения и трёх расширений, возможности Network Extension и App
  Group, запись в App Store Connect, API-ключ); что и как проверять тестировщику; как присылать отзыв и сбой.
- CI: в `ios.yml` — задача «Подпись и выгрузка в TestFlight», которая включается только при наличии секретов
  (`ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`, `APPLE_TEAM_ID`): архив с автоматической подписью через API-ключ, номер
  сборки = номер запуска CI, `xcrun altool --upload-app`. Без секретов — пропускается, как сейчас (неподписанный `.ipa`).
- `ITSAppUsesNonExemptEncryption` в Info.plist приложения и расширений — по образцу апстрима.
- Готовность: инструкция проверена «вслепую» по шагам (без аккаунта — до шага регистрации); задача CI проходит в режиме
  «пропуска» и валидируется `xcodebuild -showBuildSettings` с подстановкой тестовых значений.

## Блок F. Скорость в моменте

- Android: главный экран (под счётчиками объёма) и уведомление в шторке — «↓ 4,2 МБ/с ↑ 380 КБ/с · всего ↓ 1,2 ГБ ↑ 40 МБ»;
  обновление раз в секунду, без перерисовки при неизменной строке; сглаживание по 2 последним секундам.
  Источник — `StatusMessage.downlink/uplink` sing-box; для SSTP/L2TP и AmneziaWG — разность счётчиков в секунду.
- iOS: главный экран (статистика уже приходит из расширения), виджет — текущая скорость.
- ПК и Classic: подсказка значка трея и плашка (на главном экране ПК скорость уже есть).
- Готовность: на эмуляторе под нагрузкой (стенд 0.7.9) скорость в шторке совпадает с `/proc/net/dev` в пределах 10 %.

## Блок G. Идеи Meridian и устойчивость (перенесено из плана 0.7.9)

- Пресет «Российские приложения напрямую» (свой список пакетов банков и госуслуг, из установленных — только
  присутствующие; на ПК — по процессам) + подсказка при первом запуске.
- Запасной источник обновлений (зеркало) и загрузка обновления через уже поднятый туннель.
- Отмена подключения повторным нажатием на кнопку во время «Подключение…».
- Хвост 7a: признак смерти сервиса sing-box — сверить, нужен ли до перехода на libbox 1.14 (0.8.4).

## Чего нет в 0.7.11 (осознанно)

- Мастер узла OpenFlux («Своя нода», «Без сервера») — 0.8.0 «Мои серверы», где уже будет SSH-слой.
- JS-транспорты OpenFlux (у апстрима экспериментальные, с доверием к ключу автора) — отслеживаем, не берём.
- Ночной канал обновлений — позже, вместе с запасным источником, если понадобится.

## Порядок работ и проверка

A → B → C → F → G → D → E (документ E пишется сразу, CI-часть — в конце). После каждого блока: тесты, e2e, эмулятор;
перед релизом — пересборка клиентов OpenFlux/olcRTC (урок 0.7.8–0.7.9), полный прогон CI, `scripts/release.sh`.

## Риски

- Формат ссылок и флаги CLI апстрима меняются быстро (метка v0.3.0 уже переставлялась) — закрепляем коммит, сверяем
  `check-updates.sh` перед релизом.
- Проверка Яндекса зависит от IP узла и cookies — без документа владельца сценарий D проверяется только частично.
- TestFlight требует платный аккаунт Apple Developer; без него блок E — документ и подготовленный CI.
