# 0.8.3 — обслуживание: свежие ядра и панели, пинг на главной и в «Моих серверах», фикс Linux-обновления

Ветка `claude/0-8-3-alpha` (от `master` = выпуск 0.8.2, 31.10.2026). Порядок подверсий: **0.8.3-a** → 0.8.3-b → 0.8.3-rcN → 0.8.3.
`versionCode` — 82 и выше (0.8.2 = 81). Ничего не ломаем — только чиним и обновляем проверенное.

## 3. Linux self-update

Причина: `scripts/package-desktop.sh` собирает DEB/RPM через `jpackage --app-version "${VERSION%%-*}"` — суффикс `-a`/`-rc1`
отбрасывался, и у всех пре-релизов был одинаковый NEVR `hydra-vpn-0.8.2-1`. apt/rpm на Simply Linux считали «обновление»
не новее и удаляли приложение.

Кодируем ступень в третье число (та же схема, что `winPkgVersion`): `0.8.2` → `0.8.299`, `0.8.3-a` → `0.8.310`, `0.8.3-rc1` → `0.8.361`.

| Файл | Что меняется |
|---|---|
| `scripts/package-desktop.sh` | функция `pkg_version()`; `--app-version "$(pkg_version "$VERSION")"` вместо `"${VERSION%%-*}"` |
| `desktop/build.gradle.kts` | `linuxPkgVersion = winPkgVersion`; `packageVersion = linuxPkgVersion` в блоке `linux {}` |

## 4. Пинг на главной (Windows / ПК)

`verify()` по-прежнему ставит `delayMs` (HTTP через туннель) — он нужен Classic и трею. На главной Compose-вкладке
показываем **настоящий пинг** `Ping.profile(выбранный сервер)`, обновляемый каждые ~5 с, пока CONNECTED.

| Файл | Что меняется |
|---|---|
| `desktop/…/AppController.kt` | в `UiState` поле `serverPingMs: Int?`; цикл `watchServerPing(sessionId, profile)`; обнуление `serverPingMs` в `launchSession`, `connectPptp`, `disconnect`, `onCoreExit` |
| `desktop/…/ui/HydraApp.kt` | цвет кольца (стр. 193) и текст (стр. 227) берут `serverPingMs` вместо `delayMs`; «Проверка через туннель» убрана с главной |
