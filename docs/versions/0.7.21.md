# 0.7.21 — Kaspersky не блокирует Hydra для Windows (план; номер не выпускался)

> **Состояние (15.10.2026):** версия 0.7.21 не выпускалась — после 0.7.20 работа ушла в 0.8.0. Предупреждение об антивирусе живёт в README
> и в заметках релизов (`scripts/release.sh`); план ниже не выполнен и стоит в очереди дорожной карты («Windows: ложное срабатывание
> антивируса»). Документ восстановлен 15.10.2026 из ветки `claude/kaspersky-0-7-20-block-06cb6e`, которая не была влита.

Запрос владельца 10.10.2026 (скриншот «Мониторинг активности» Kaspersky Standard 21.25): после установки 0.7.20 Касперский пометил `Hydra.exe`
(`C:\Users\Chist\AppData\Local\Hydra`, в отчёте «OpenJDK Platform binary») как **«Троянское приложение: PDM:Trojan.Win32.Generic»**, создал резервную копию,
удалил объекты (18:27:32) и не дал запустить программу. Задача: чтобы Hydra для Windows не блокировалась, выпуск 0.7.21.

## Что показывает отчёт

- `PDM:` - это **эвристика поведения** (Proactive Defense / System Watcher), а не сигнатура. Касперский не нашёл известного вредоносного кода, он увидел
  набор действий процесса, похожий на троян. Поэтому «просто пересобрать» мало: нужно убрать подозрительные действия и дать доверие (подпись, репутация).
- Файл неподписанный (`vendor = "Hydra VPN"` в jpackage - это текст, а не подпись), установка в `%LOCALAPPDATA%` (per-user MSI), без репутации в KSN.
  Для эвристики это усугубляющие признаки: каждый новый релиз - «новый неизвестный файл».
- Точный триггер отчёт не называет. Ниже - причины по коду, **по убыванию вероятности**. Это гипотезы: подтвердить можно только на ПК с Kaspersky (шаг 0).

## Шаги

### Шаг 0. Подтвердить причину (владелец, ~30 минут; без этого остальное - ставка)
1. В Kaspersky: «Отчёты» -> «Обнаружение угроз»/«Мониторинг активности» -> строка «Обнаружен вредоносный объект» -> **полный текст** (там же «Путь к объекту», «Хэш», «Процесс-инициатор»,
   обычно перечислены вызванные действия). Прислать снимок или текст целиком.
1a. Из отчёта 10.10.2026 18:27 известно: вердикт вынесен компонентом «Мониторинг активности» над **запущенным** `Hydra.exe` (PID 2380), т.е. триггер - действие процесса,
   а не файл при установке. Какое именно - в отчёте нет. Чтобы увидеть без Касперского: Process Monitor (Sysinternals), фильтр `Parent PID`/`Process Name is Hydra.exe`,
   операция `Process Create` - запустить Hydra (при отключённой защите или в виртуальной машине без Касперского), нажать «Подключить» и «Отключить», сохранить журнал.
   Сообщить также, что делали в 18:27 (установка, первый запуск, подключение).
1b. Различить «виновато обновление» и «виноват сам файл 0.7.20»: поставить 0.7.20 **вручную** (скачать MSI в браузере, запустить, не через «Обновить») на чистую систему/ВМ с Kaspersky.
   Сработало - дело в файле (подпись, репутация, поведение при работе). Не сработало - дело в цепочке «Обновить» (скачать, `msiexec`, перезапуск): шаг 1.4.
2. Восстановить файлы из карантина («Карантин» -> «Восстановить» и «Добавить в исключения»), чтобы вернуть работу 0.7.20 сейчас.
3. Бисекция (0.7.15 уже проходила): скачать MSI из GitHub Releases **вручную** и установить на ПК с Касперским, сняв исключение для папки Hydra (или в ВМ). Порядок: **0.7.18**
   (страж-PowerShell и перезапуск от администратора, без PPTP). Сработало - причина №1/№2 (проверить 0.7.16, чтобы сузить). Не сработало - **0.7.19** (PPTP: `WindowsPptp`, MPPE/RC4, GRE):
   сработало - №3. Не сработало - причина в 0.7.20 (TG WS, №6). Если сработает на всём, кроме 0.7.15 - репутация новых файлов, тогда подпись (шаг 3) и заявка (шаг 4).
4. Для выбранного файла получить вердикт других движков: <https://www.virustotal.com> (если ложное срабатывание только у Касперского - подаём заявку, шаг 5).

### Шаг 1. Убрать PowerShell и скрытые приёмы (код, Windows; Classic тоже)
1. **Страж прокси без PowerShell.** Вместо `powershell -EncodedCommand` запускать тот же `Hydra.exe` с аргументом `--proxy-guard <pid> <файл копии>`: режим без окна,
   ждёт процесс (`ProcessHandle.onExit`/JNA `WaitForSingleObject`), возвращает прокси тем же JNA-кодом `SystemProxy.restore` (он уже есть). Никаких `-WindowStyle Hidden`,
   `-ExecutionPolicy Bypass`, `-EncodedCommand`. Тест: юнит-тест разбора аргументов и сценарий «процесс убит - прокси возвращён» (как в 0.7.16).
2. **Перезапуск от администратора** через `ShellExecuteExW` с глаголом `runas` (JNA `Shell32`), а не `powershell Start-Process -Verb RunAs`. Отказ в UAC даёт код ошибки без побочных эффектов (как сейчас).
3. **PPTP без PowerShell.** Телефонная книга `rasphone.pbk` пишется приложением (запись «Hydra PPTP»: `PhoneNumber`, `VpnStrategy=1`, `DataEncryption=256`/`0`, `AuthRestrictions`),
   поднимается `rasdial "Hydra PPTP" /phonebook:<файл>`; пароль не в аргументах, а через `RasSetCredentials` (JNA, `rasapi32`) и сразу стирается. Состояние - `RasGetConnectStatus`/`rasdial`
   без аргументов. Если JNA-путь не успеем, в 0.7.21 PPTP на Windows временно отключается с честным сообщением, а вернётся в 0.7.22 (решение владельца).
4. **Самообновление без .cmd.** Подмену папки делает копия самого `Hydra.exe` в режиме `--apply-update <pid> <корень> <новая папка>` (не скрипт в `%TEMP%`), с тем же откатом через `.old`.
   Для Classic (Hydra.vbs) - то же через `javaw`. Для MSI/EXE (путь владельца) - не запускать `msiexec` скрыто из Java: показать файл и открыть его обычным запуском через оболочку (`ShellExecute open`, окно установщика видно
   пользователю), после установки новая Hydra стартует **вручную пользователем** (без авто-запуска сразу после записи файла), либо тихая установка только по явному «Установить сейчас».
5. Нигде в коде не должно остаться: `-EncodedCommand`, `-ExecutionPolicy Bypass`, `-WindowStyle Hidden`. Добавить тест-страж (`grep` по исходникам в юнит-тесте): такие строки в `desktop/src/main` не допускаются.

### Шаг 2. Снизить «шум» упаковки
- Метаданные Windows-файла: `ProductName`, `FileDescription`, `CompanyName`, `LegalCopyright`, `FileVersion` (у jpackage по умолчанию «OpenJDK Platform binary» - как в отчёте);
  задать через `--win-...`/ресурсы launcher'а или `rcedit` в `scripts/package-desktop.sh`.
- Манифест: `asInvoker` (не требуем админа), без `requireAdministrator`.
- Каждое вложенное ядро (`sing-box`, `xray`, `olcrtc`, `openflux`, `ciadpi`) - проверка SHA-256 против официального релиза (уже в `scripts/check-updates.sh` для sing-box/xray) и **без** UPX/упаковщиков.
- Установка: оставить per-user MSI, но добавить в README и в мастер первого запуска короткую подсказку для антивирусов («если защита блокирует - добавьте папку Hydra в исключения»).

### Шаг 3. Доверие: подпись кода (главное долгосрочное решение)
- Подписывать `Hydra.exe`, MSI, EXE и ядра **Authenticode**. Варианты для проекта GPL-3.0:
  1. **SignPath Foundation** - бесплатная подпись для открытых проектов (нужна заявка, сборка в GitHub Actions) - **рекомендую**;
  2. Azure Trusted Signing / платный OV/EV-сертификат - быстрее, но платно и нужно юрлицо или ИП.
- Для macOS уже в списке «нотаризация»; здесь - только Windows.
- Подписанный файл не отменяет эвристику, но резко снижает шанс PDM и даёт стабильную репутацию между версиями. Заявка на SignPath - действие владельца (аккаунт и согласие на условия).

### Шаг 4. Ложное срабатывание в «Лабораторию Касперского» (владелец, после подписи или сразу)

## Не входит
- Обход Касперского «умолчанием» (отключение защиты, исключения без ведома пользователя) - исключено; только честные меры.
- Подпись Android/iOS/macOS (отдельные пункты дорожной карты).

## Риски
- Без подписи и репутации эвристика может срабатывать и после шага 1: тогда остаются подпись (шаг 3) и заявка (шаг 4). Гарантии «Касперский больше не ругается» дать нельзя.
- Переписывание стража, перезапуска и самообновления затрагивает отключение прокси - самую чувствительную часть (0.7.16): нужна повторная проверка «Отключить» на Windows.
