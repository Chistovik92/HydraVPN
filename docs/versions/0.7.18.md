# План 0.7.18 - ссылки без потерь параметров, устойчивость туннеля

Продолжение ревизии кода 10.10.2026 (выпущено в тот же день).

## Задачи и результат

| № | Задача | Результат |
|---|---|---|
| 1 | Терялся заголовок `Host` для WebSocket | параметр `host=` (vless/trojan) и `host` (vmess) -> `transport.headers.Host`; транспорт `httpupgrade` |
| 2 | `insecure` / `allowInsecure` / `allow_insecure` игнорировались | доходят до `tls.insecure` (VLESS, Trojan, Hysteria2, TUIC) |
| 3 | uTLS добавлялся в Hysteria2 и TUIC | для QUIC не применяется; пустой отпечаток -> `chrome` |
| 4 | Раздельное туннелирование «только эти» с пустым списком пускало в туннель всё | при отсутствии доступных пакетов в туннель идёт только Hydra, причина в журнале |
| 5 | `HydraVpnService.onDestroy` не освобождал tun и ядро | `releaseTun()` |
| 6 | TG WS после «Отключить» оставлял открытые соединения, число потоков не ограничено | `stop()` закрывает соединения, потолок 256 |
| 7 | Роутер по HTTP на Android: «CLEARTEXT communication not permitted» | понятная причина (система запрещает соединение без TLS) |

## Не вошло

- Kill switch в TUN на ПК (по-прежнему только режим «Системный прокси»), транспорт `xhttp` (sing-box не поддерживает), `CoreRunner.start()` держит блокировку на время ожидания порта.

## Критерии готовности и что проверено

- Юнит-тесты: `wsHostHeader`, `httpUpgradeTransport`, `quicProtocolsHaveNoUtlsAndKeepInsecure`, `tcpProtocolsKeepUtls` (Android), разбор ссылок -> конфиг (ПК).
- Не проверено на устройстве: изменения `HydraVpnService` (раздельное туннелирование, `onDestroy`).
