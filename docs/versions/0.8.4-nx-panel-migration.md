# NX Panel 0.1.2: миграция Nexora → NX (этап 2, 0.8.4-b)

Ветка `claude/0-8-4-alpha`. Исследование завершено 21.11.2026; контракт собран из
`nx-panel/panel@v0.1.2` (install.sh, README, docs) и docs.nx-panel.org. Исходники NX Panel **закрыты**
(README: «The source is not public»), поэтому точные JSON-схемы запросов доступны только из
`/api/openapi.json` живого стенда — схему надо сверять на стенде перед релизом.

## Что меняется (Nexora v0.0.6 → NX v0.1.2)

| Аспект | v0.0.6 (сейчас) | NX 0.1.2 |
|---|---|---|
| Репозиторий | `Nexora-VPN/panel` | `nx-panel/panel` |
| Бинарь панели | `nexora-panel` | `nx-panel` (в PATH) |
| HOME | `/opt/nexora-panel` | `/opt/nx-panel` |
| DATA | `/var/opt/nexora` | `/var/opt/nx-panel` |
| Служба | `nexora-panel` | `nx-panel` |
| Нода: бинарь/служба | `nexora-node` | `nx-node` |
| Нода: HOME/DATA | `/opt/nexora-node`, `/var/opt/nexora-node` | `/opt/nx-node`, `/var/opt/nx-node` |
| Порт ноды | 62050 | 62050 (не изменился) |
| Первичная настройка | `POST /api/setup` (JSON) | CLI `nx-panel migrate -user -pass` + `nx-panel ingress reset -listen 127.0.0.1:PORT -yes` |
| Установка | `bash install.sh --version X --node-version X` | `bash install.sh --version X` (нода теперь отдельный `/install-node.sh`) |
| Установка ноды | SSH install-job через API панели | `/install-node.sh` с одноразовым токеном, или SSH-автоустановка панели |
| Вход | `POST /api/login` + cookie | `POST /api/login` + cookie (не изменился) |
| Токен API | `POST /api/tokens` | `POST /api/tokens` (области изменились: теперь `:read`/`:write`/`:install`; поле `role` осталось) |

## Ключевые решения (требуют подтверждения владельца)

1. **Headless-установка владельца.** NX убрал JSON `/api/setup` с `username`+`password`+`listenPort`.
   Варианты:
   - **A (рекомендуется):** после `install.sh` вызвать `nx-panel migrate -user U -pass P` (создаёт
     владельца без браузера), затем `nx-panel ingress reset -listen 127.0.0.1:PORT -yes` (петля).
     Панель слушает 127.0.0.1 и открывается через SSH-туннель Hydra — как сейчас.
   - B: оставить wizard и открывать его пользователю по ссылке `setup?t=TOKEN` (ломает текущий
     «однокнопочный» деплой Hydra).

2. **Установка ноды.** NX теперь ставит ноду через `/install-node.sh` с одноразовым токеном либо
   SSH-автоустановкой панели. Текущий `NexoraApi.awaitInstall` (SSH install-job через API) надо
   перевести на новый `/install-node.sh` (manual) или на `/api/v1/nodes/{id}/install` (SSH auto).

3. **Версия закрепляется** `NX_TAG = "v0.1.2"` + SHA-256 `install.sh`
   (`3219a450b02abcbd75cfba8626898e787999acff`) в `ScriptPins.kt`.

## Затронутые файлы (Hydra)

- `shared/.../servers/NexoraPanel.kt` — пути/служба/бинарь, setup-флоу, нода, uninstall.
- `shared/.../servers/ScriptPins.kt` — `NEXORA_TAG` → `v0.1.2`, репо + SHA-256.
- `shared/.../servers/MyServerService.kt` — `deployNexora` (setup-token → CLI migrate/ingress),
  `restartPanel`, `uninstallPanel`.
- `shared/.../servers/ServerOps.kt` — `statusCommand`/`parseStatus` (путь `nx-panel`, служба `nx-panel`).
- `shared/.../servers/PanelNodes.kt` — план установки ноды NEXORA.
- `shared/.../servers/PanelBackups.kt` — путь копии `/var/opt/nexora` → `/var/opt/nx-panel`.

## Порядок работ

1. Закрепить `ScriptPins` (тег + SHA install.sh), переписать константы и пути `NexoraPanel`.
2. Setup: CLI `migrate` + `ingress reset`; создание токена `/api/tokens` — перепроверить схему на стенде.
3. Нода: `/install-node.sh` (manual) или SSH-auto; согласовать с владельцем.
4. `ServerOps`/`PanelNodes`/`PanelBackups` — пути и проверки.
5. Собрать shared/desktop, прогнать тесты; сверка схем на живом стенде NX (обязательна из-за закрытых
   исходников).
