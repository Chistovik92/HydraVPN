## Поручение владельца (14.10.2026)

1. «При нажатии „Добавить“ конфиг AmneziaWG не импортируется». Затем уточнение: **в клиенте вообще нельзя добавить конфиг AmneziaWG или обычного WG, как и серверы многих других протоколов; не импортируется и конфиг уже созданного сервера** — это ошибка rc2, её исправление и есть rc3.
2. «При включённом VPN (по любому протоколу) подключение к серверам должно идти через этот туннель»: бывают серверы, недоступные из страны без VPN; приложение не давало подключиться к ним и с VPN (SSH «Моих серверов», подписки).
3. После выпуска rc3 — сразу к 0.8.1-a (внести в неё эти правки, доделать и тоже выпустить пре-релизом). См. [`0.8.1.md`](0.8.1.md).
4. Документировать подробно по каждой версии и подверсии (этот файл — часть выполнения).

## Что изменено

### Импорт `.conf` (Android)
- `ImportDetector`: `isConf = "[Interface]" in text`; JSON-отказ только если не `.conf`.
- `MainViewModel.importAuto(texts, subName)`: если импортируется **один** сервер и задано имя — оно главнее имени из `.conf` (мастер «Мои серверы» передаёт имя клиента; кнопка «Добавить в Серверы» тоже).
- Тесты: `ImportDetectorTest.wholeConfIsNotJson`.

### Ручное добавление (Android)
- Новый `data/subscription/ManualServer.kt` — чистая функция `build(...) → ServerProfile?` и признаки полей (`kind`, `needsUser/Sni/Method/Secret2`, `defaultPort`). Значения совпадают с тем, что кладёт `LinkParser` из ссылки (security, alpn, `extra`).
- Новый `ui/screens/AddServerDialog.kt` (вынесен из `ServersScreen.kt`; `OutlinedActionButton` стал `internal`). Виды формы: `CREDENTIALS` / `CONF` (вставка `.conf` → `importAuto`) / `LINK_ONLY` (OpenFlux, olcRTC, ByeDPI, WDTT → кнопка «Импорт»).
- Строки `field_uuid/password/username/cipher/sni`, `manual_conf_*` — в `values` (en) и `values-ru`; uk/fa/zh берут английские (осознанно, ресурсы-фолбэк).
- Тесты: `ManualServerTest`.
- ПК: ручной формы никогда не было (только вставка/импорт) — поле вставки стало многострочным.

### Трафик Hydra через VPN
- Настройка `appThroughVpn` (по умолчанию **включена**): Android — `VpnSettingsRepository` (ключ DataStore `app_through_vpn`), Настройки → Безопасность; ПК — `DesktopSettings.appThroughVpn`, Настройки → Безопасность.
- **Android** (`HydraVpnService.establishTun`): `appInTunnel = настройка && !AppTunnelPolicy.needsAppBypass(...)`; при `true` не вызывается `addDisallowedApplication(packageName)` (режимы OFF/EXCLUDE), а в режиме INCLUDE приложение добавляется в разрешённые. В журнал пишется строка «Трафик самой Hydra … через туннель / мимо туннеля».
- `vpn/core/AppTunnelPolicy.kt` решает, нужно ли оставить приложение вне tun (иначе петля). Приложение **остаётся вне туннеля**, если: движок не из `{SINGBOX, AWG, USERSPACE}` (то есть OpenFlux, olcRTC, ByeDPI, Xray, WDTT), включён обход DPI, у профиля есть цепочка `via`, правила/группы ведут на `dpi`/`tgws` или на узел-подпроцесс (неизвестный узел считается опасным). Причина: сокеты подпроцессов принадлежат UID приложения, `protect()` на них не повесить; у sing-box (libbox: `autoDetectInterfaceControl`), AmneziaWG, SSTP/L2TP/PPTP сокеты защищает само приложение.
- Тесты: `AppTunnelPolicyTest`.
- **ПК, TUN:** `Platform.processExecutable` убран из `bypass`, если `appThroughVpn` и в плане нет TG WS (TG WS живёт внутри процесса Hydra — его сокеты зациклились бы). Процессы-клиенты (Xray, olcRTC, OpenFlux, ByeDPI) в списке обхода остаются.
- **ПК, «прокси»:** `desktop/core/AppNet.kt` — `ProxySelector` по умолчанию ставится при старте (`Main.kt`), пока ядро поднято (`AppNet.use(port)` после запуска, `AppNet.clear()` в `CoreRunner.stop()`), все не локальные HTTP-запросы идут в HTTP-прокси ядра `127.0.0.1:<порт>`; `shared/.../servers/AppProxy.kt` + `JschSsh.newSession` направляют SSH через `ProxySOCKS5`. `Subscriptions.http` получил `.proxySelector(AppNet.selector)` (OkHttp запоминает селектор при создании). Тест: `AppNetTest`.

## Как проверено

- Юнит-тесты: `:app:testStubDebugUnitTest`, `:desktop:test` — зелёные (новые: `ImportDetectorTest`, `ManualServerTest`, `AppTunnelPolicyTest`, `AppNetTest`).
- Сборка `:app:assembleNativeDebug` (нужны `app/libs/*.aar` из основной копии — они в `.gitignore`; скопировать `cp -rn /e/Git/HydraVPN/app/libs/* app/libs/`).
- Эмулятор `hydra35` (Android 15): debug-сборка `ru.gidravpn.hydra.debug` (uid отличается от release `ru.gidravpn.hydra` — не перепутать при `adb install`), импорт `awg://` → подключение AmneziaWG: в журнале «Трафик самой Hydra (SSH, подписки) идёт через туннель», `ip rule` показывает единый `uidrange 0-99999 lookup <tun>` (раньше — «дырка» под uid приложения), после «Отключить» `tun0` отсутствует.
- **Не проверено:** сквозной SSH/подписка через живой VPN на реальном сервере, ПК-режимы TUN/прокси вживую, ручная форма на устройстве (только юнит-тесты), release-сборка с R8.

## Известные ограничения и заметки на будущее

- Пинг на Android идёт мимо туннеля (`PingMeasurer` вызывает `SocketGuard.protect`) — намеренно. На ПК в режиме TUN пинг идёт через туннель (искажает), в режиме «прокси» — напрямую.
- Режимы с подпроцессами и TG WS по-прежнему оставляют Hydra вне туннеля. Чтобы закрыть: пускать трафик подпроцессов правилом sing-box по `process_path`/UID вместо исключения приложения.
- Практика сборки: Bash-heredoc с `'''` ломает инструмент Bash — скрипты правок писать файлом через Write; правки Kotlin-файлов с `\n` — через Edit/Write.
- Версия: `versionCode = 65`, `versionName = "0.8.0-rc3"`.
