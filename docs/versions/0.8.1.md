## 0.8.1-a — альфа (14.10.2026)

- Панель **3x-ui**: установка закреплённым тегом (последний выпуск узнаётся через GitHub API и показывается до запуска), вход в API
  **по токену** из `/etc/x-ui/install-result.env` (решение владельца 11.10.2026), инбаунд VLESS + Reality и первый клиент, готовая
  ссылка сразу в «Серверы»; пользователи панели (список, добавить, ссылка, удалить) — по токену, без SSH (`XuiPanel.kt`).
- **«У меня уже есть панель»**: подключить готовую 3x-ui по адресу и токену, без SSH и установки.
- Экраны простым языком и понятные ошибки (`FriendlyText.kt`) — в rc4 перенесены в 0.8.0.
- Пароль панели в буфере — 30 секунд; выпуск альфы из ветки (`scripts/release.sh` для `-a`/`-b`).

## 0.8.1-b — бета (14.10.2026)

|---|---|

| **Смена панели** (запрос владельца 14.10.2026) | Удалить одну панель и поставить другую или вернуться к AmneziaWG — на одном сервере, без переустановки ОС. Проверено вживую: 3x-ui → s-ui → x-ui → очистка → AmneziaWG |

| Порты панелей | Через общий учёт открытых Hydra портов (`/etc/hydra/fw.list`) — закрываются при удалении и очистке |

## Справка: панели

| Панель | Установка | Учётные данные | Вход в API |
|---|---|---|---|
| 3x-ui (v3.9–v3.10) | `install.sh vX.Y.Z` с `XUI_NONINTERACTIVE=1`, `XUI_USERNAME`, `XUI_PASSWORD`, `XUI_PANEL_PORT`, `XUI_WEB_BASE_PATH` | задаёт Hydra; итог — `/etc/x-ui/install-result.env` (с `XUI_API_TOKEN`) | Bearer-токен |
| s-ui (v1.6.4) | `install.sh vX.Y.Z`, на вопрос «изменить настройки» — «нет»; затем `sui setting -port -path`, `sui admin -username -password` | задаёт Hydra | `POST {путь}api/login` (`user`, `pass`, заголовок `Origin`) |
| x-ui alireza0 (v1.14.0) | `install.sh vX.Y.Z` с `XUI_NONINTERACTIVE=1`; затем `x-ui setting -username -password -port -webBasePath` | задаёт Hydra | `POST {путь}login` (`username`, `password`) |

3x-ui и x-ui ставятся в один каталог `/usr/local/x-ui` — одновременно стоять не могут (Hydra проверяет перед установкой).
Удаление 3x-ui — `printf 'y\n' | /usr/bin/x-ui uninstall` (`/usr/local/x-ui/x-ui` — бинарь панели, не скрипт управления).

Методы API 3x-ui, которыми пользуется Hydra: `POST /panel/api/setting/all` (проверка токена), `GET /panel/api/server/getNewX25519Cert`
(ключи Reality), `GET /panel/api/inbounds/list/slim`, `POST /panel/api/inbounds/add`, `POST /panel/api/clients/add`,
`POST /panel/api/clients/del/{email}`, `GET /panel/api/clients/list`, `GET /panel/api/clients/links/{email}`.

### Что увидел владелец в rc1 (VPS 89.125.168.20, телефон, 15.10.2026 01:14)

Панель 3x-ui v3.10.2 переустановлена из rc1: HTTPS на IP выдался и работает, подписка `https://…:2096/…` импортирована. Подключение
(VLESS + gRPC + REALITY, vk.com, порт 443) — «Подключено», 12 КБ / 5 КБ за 7 с, YouTube не грузится. Подписка «Vless grpc» с
другого сервера на том же телефоне работает.

### Причина — не блокировки (воспроизведено на стенде)

| Проверка (WSL, 3x-ui v3.10.2 = Xray-core 26.10.10) | Итог |
|---|---|
| sing-box 1.12.25 (ядро Hydra для VLESS по умолчанию), конфиг из кода Hydra, 4 инбаунда: gRPC × vk.com / github.com / ya.ru, XHTTP × vk.com | отказ на всех: `reality verification failed` |
| то же, отпечатки uTLS chrome, firefox, safari, ios, edge, randomized, 360, qq | отказ на всех |
| клиент Xray-core 26.10.10 на сервере, тот же инбаунд | 500 КБ, работает |
| **Xray-core 26.9.30 Hydra**, конфиг `XrayConfigBuilder`, те же 4 инбаунда | **по 1,9 МБ за 1–7 с** |

С Xray-core 26.9.8 сервер REALITY требует в ClientHello гибридный ключ X25519MLKEM768 (коммит REALITY `8cdf7bf9c7f0`); sing-box его
не шлёт ни в одной версии (1.12.25, 1.14, 1.15-alpha) — сервер считает клиента чужим и отдаёт сайт маскировки. Ошибка известна
([SagerNet/sing-box#4520](https://github.com/SagerNet/sing-box/issues/4520), без ответа с 11.09.2026). «Vless grpc» владельца, видимо, на
сервере со старым Xray (< 26.9.8), где sing-box ещё пускают. Откатывать Xray на сервере (26.7.28) не стали: в 26.9.8 — исправление
утечки памяти REALITY, а у 26.7.x своя проверка версии клиента.

Как вход за пользователя устроен у каждой панели (проверено вживую): 3x-ui v3.10.2 — `POST {адрес}/login` (`username`, `password`) с
заголовком `X-CSRF-Token` со страницы входа, без него 403; x-ui v1.14.0 — `POST {адрес}login`; s-ui v1.6.4 — `POST {адрес}api/login`

### Обход блокировок — на чём основан выбор (разведка 15.10.2026)

- ТСПУ с 17.02.2026 режет по косвенным признакам: SNI не совпадает с сетью, из которой отвечает сервер; нестандартный для браузера
  характер соединения ([oblako.sh](https://oblako.sh/wiki/ru/rukovodstva/blokirovki-reality-self-steal)). Отсюда — порт 443 и выбор маскировки.
- При «белых списках» мобильных операторов проходит только SNI из списка (vk.com, ya.ru) и/или IP из разрешённых диапазонов
  ([обсуждение в 3x-ui](https://github.com/MHSanaei/3x-ui/issues/3672), [Хабр](https://habr.com/ru/articles/1021160/)); зарубежный донор
  без узлов в РФ (github.com) не спорит с IP сервера, но в «белых списках» не пройдёт — поэтому выбор оставлен пользователю.
- Самый надёжный вариант — **self-steal на своём домене** (Reality ведёт на свой сайт на том же сервере): это следующий шаг, нужен домен —
  см. «Аренда доменов» в [дорожной карте](../ROADMAP.md).
