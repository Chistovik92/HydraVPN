# 0.8.1 — панели 3x-ui, s-ui, x-ui

Ветка `claude/0-8-1-alpha` (в `master` — после выпуска 0.8.0 и проверки владельцем). Опирается на «Мои серверы» 0.8.0
([0.8.0](0.8.0.md), [0.8.0-rc4](0.8.0-rc4.md)). Порядок подверсий: **0.8.1-a** (14.10.2026) → **0.8.1-b** (14.10.2026) → 0.8.1-rcN → 0.8.1.

> Полные тексты прежних версий этой заметки — в архиве: [исходный план 12.10.2026](../archive/0.8.1-plan-2026-10-12.md) (блоки A–H,
> все методы API 3x-ui, адрес подписки), [заметки альфы 0.8.1-a](../archive/0.8.1-a-notes.md) (что и как сделано, чем проверено,
> таблица «Осталось»), [дорожная карта альфы](../archive/ROADMAP-0.8.1-a.md).

## 0.8.1-a — альфа (14.10.2026)

- Панель **3x-ui**: установка закреплённым тегом (последний выпуск узнаётся через GitHub API и показывается до запуска), вход в API
  **по токену** из `/etc/x-ui/install-result.env` (решение владельца 11.10.2026), инбаунд VLESS + Reality и первый клиент, готовая
  ссылка сразу в «Серверы»; пользователи панели (список, добавить, ссылка, удалить) — по токену, без SSH (`XuiPanel.kt`).
- **«У меня уже есть панель»**: подключить готовую 3x-ui по адресу и токену, без SSH и установки.
- Экраны простым языком и понятные ошибки (`FriendlyText.kt`) — в rc4 перенесены в 0.8.0.
- Пароль панели в буфере — 30 секунд; выпуск альфы из ветки (`scripts/release.sh` для `-a`/`-b`).

## 0.8.1-b — бета (14.10.2026)

Всё из [0.8.0-rc4](0.8.0-rc4.md) (сервер-сначала, сохранённый вход, очистка, исправления ByeDPI и AmneziaWG, ручной ввод всех
протоколов) **плюс** панели, встроенные в новую схему:

| Что | Как |
|---|---|
| Панель — служба на сервере | На карточке сервера раздел «Панель управления»: **«Установить 3x-ui» (рекомендуем), «Установить s-ui», «Установить x-ui»** — после входа, как AmneziaWG и OpenFlux |
| **s-ui** (alireza0, v1.6.4) и **x-ui** (alireza0, v1.14.0) — новое | Официальный установщик закреплённого тега; логин, пароль, случайные порт и путь задаёт Hydra командой самой панели (`sui admin`/`sui setting`, `x-ui setting`) — файлом 0600, не в командной строке; проверка, что панель отвечает; «Открыть панель» + пароль в буфер на 30 с. Пользователей заводят на сайте панели (API-токена у них нет) — `OtherPanels.kt` |
| Удаление и очистка | «Удалить панель» на карточке; «Очистить сервер полностью» снимает панели, **только если их ставила Hydra** (метки `/etc/hydra/xui.installed`, `sui.installed`, `xui-alireza.installed`) |
| **Смена панели** (запрос владельца 14.10.2026) | Удалить одну панель и поставить другую или вернуться к AmneziaWG — на одном сервере, без переустановки ОС. Проверено вживую: 3x-ui → s-ui → x-ui → очистка → AmneziaWG |
| **Копия базы панели** перед удалением и очисткой | База (SQLite: `/etc/x-ui/x-ui.db` у 3x-ui и x-ui, `/usr/local/s-ui/db/s-ui.db` у s-ui) копируется в `/root/hydra-backups/<панель>-<дата>.db` (0600). Каталог вне `/etc/hydra` — очистка его не трогает; из копии можно вернуть пользователей или перенести их (см. 0.8.2) |
| Совместимость записей между версиями | Запись сервера хранит незнакомые ей поля как есть (`MyServer.unknown`): переход 0.8.1 ↔ 0.8.0 больше не стирает данные. Запись панели 0.8.1-a, уже испорченная rc4, показывается как «повреждена» с кнопкой «Убрать из списка» |
| Несколько устройств | Копия записи панели `/etc/hydra/panel.json` (0600): второе устройство, добавив сервер, сразу видит панель; для 3x-ui — ещё и по `install-result.env` |
| Готовая панель по токену | Отдельная карточка без SSH (нет проверки сервера, очистки, перезагрузки) — только API панели |
| Порты панелей | Через общий учёт открытых Hydra портов (`/etc/hydra/fw.list`) — закрываются при удалении и очистке |
| Языки | Строки «Моих серверов» на украинском, персидском и китайском (до этого — английские) |

Версия: `versionName = "0.8.1-b"`, `versionCode = 68` (выше rc4 = 67 и 0.8.1-a = 66).

### Как проверено

- Юнит-тесты: Android 195, ПК 132 (в т. ч. `OtherPanelsTest`: безопасность плана — пароль только в файле 0600, закреплённый тег, учёт
  портов, метки; подхват панели вторым устройством; `XuiPanelTest`, `XuiConnectTest`, `FriendlyTextTest`, `ServerFirstTest`).
- Живой Linux (WSL Ubuntu 26.04): **3x-ui** — установка в потоке сервер-сначала → токен → инбаунд и клиент → второй пользователь → второе
  устройство подхватывает панель → полная очистка (`XuiLiveTest`); **s-ui 1.6.4 и x-ui 1.14.0** — установка, вход на панель с логином
  Hydra (`POST {путь}api/login` у s-ui с заголовком Origin, `POST {путь}login` у x-ui), подхват вторым устройством, удаление и очистка
  (`OtherPanelsTest`); AmneziaWG — весь путь rc4 (`ServerFirstTest`).
- Живой Linux: **смена панелей** 3x-ui (v3.10.2) → s-ui → x-ui → очистка → AmneziaWG, копии баз всех трёх на месте после очистки
  (`OtherPanelsTest`); **узел OpenFlux** — установка скриптом апстрима и трафик через него настоящим клиентом OpenFlux на ПК
  (`openFluxNodeLive` + `OfxNodeClientLiveTest`).
- Эмулятор Android 15 (полный APK беты): раздел панелей, установка s-ui с телефона, подключение через узел OpenFlux (страница открылась
  через туннель), испорченная запись альфы показывается честно.
- **Не проверено:** настоящий VPS и телефон владельца; HTTPS панели; встроенный WebView.

## Осталось до 0.8.1

| Что | Почему не в бете |
|---|---|
| **HTTPS панели** (`XUI_SSL_MODE=ip|domain` у 3x-ui, сертификаты у s-ui/x-ui) | сертификат требует настоящего IP или домена и открытого порта 80 — честно проверить на стенде нельзя; нужен VPS |
| **Встроенный вход в панель (WebView на Android)** | сейчас браузер + пароль в буфере на 30 с — работает; WebView — удобство |
| Пользователи s-ui и x-ui прямо в Hydra (по cookie-сессии) | у s-ui своя модель (sing-box), у x-ui — старый API 3x-ui; переносим в 0.8.2 вместе с «подпиской в один клик» |
| Закрыть порт панели извне (доступ только через VPN/SSH) | «ничего наружу без согласия» — нужен отдельный переключатель |
| Проверка владельцем на VPS, телефоне и ПК | — |

## Справка: панели

| Панель | Установка | Учётные данные | Вход в API |
|---|---|---|---|
| 3x-ui (v3.9–v3.10) | `install.sh vX.Y.Z` с `XUI_NONINTERACTIVE=1`, `XUI_USERNAME`, `XUI_PASSWORD`, `XUI_PANEL_PORT`, `XUI_WEB_BASE_PATH` | задаёт Hydra; итог — `/etc/x-ui/install-result.env` (с `XUI_API_TOKEN`) | Bearer-токен |
| s-ui (v1.6.4) | `install.sh vX.Y.Z`, на вопрос «изменить настройки» — «нет»; затем `sui setting -port -path`, `sui admin -username -password` | задаёт Hydra | `POST {путь}api/login` (`user`, `pass`, заголовок `Origin`) |
| x-ui alireza0 (v1.14.0) | `install.sh vX.Y.Z` с `XUI_NONINTERACTIVE=1`; затем `x-ui setting -username -password -port -webBasePath` | задаёт Hydra | `POST {путь}login` (`username`, `password`) |

3x-ui и x-ui ставятся в один каталог `/usr/local/x-ui` — одновременно стоять не могут (Hydra проверяет перед установкой).
Удаление 3x-ui — `printf 'y\n' | /usr/bin/x-ui uninstall` (`/usr/local/x-ui/x-ui` — бинарь панели, не скрипт управления).

Методы API 3x-ui, которыми пользуется Hydra: `POST /panel/api/setting/all` (проверка токена), `GET /panel/api/server/getNewX25519Cert`
(ключи Reality), `GET /panel/api/inbounds/list/slim`, `POST /panel/api/inbounds/add`, `POST /panel/api/clients/add`,
`POST /panel/api/clients/del/{email}`, `GET /panel/api/clients/list`, `GET /panel/api/clients/links/{email}`.
