## Почему нужна Hydra Classic

Обычная Hydra для ПК — Compose Desktop. Его графическая библиотека Skiko выпускается только для `windows-x64`,
`windows-arm64`, `linux-x64`, `linux-arm64`, `macos-x64`, `macos-arm64`: 32-битных библиотек нет, и собрать их нельзя
(это нативный код Google Skia). Кроме того, Compose требует Java 17, а она на Windows 7 не поддерживается.

**Hydra Classic** — то же приложение с другой оболочкой:

- общий код: `AppController`, хранилище, парсеры ссылок и подписок, сборка конфигов sing-box/Xray, запуск ядер,
  системный прокси, самообновление, трей (всё в `desktop/src/main`, без Compose);
- своё окно на Swing (`desktop/src/lite`): вкладки «Главная», «Серверы», «Подписки», «Маршруты», «Настройки», «Журнал»;
- Java 11 (последняя, что работает на Windows 7; байт-код модулей `shared` и Classic — Java 11);
- настройки и данные — те же файлы, что у обычной Hydra: можно перенести резервной копией.

Чего в Classic нет: управления роутерами HydraVPN for Router (есть в обычной Hydra и на Android); olcRTC и OpenFlux
на Windows (их собирает обычный Go, он не запустится на Windows 7); AmneziaWG, SSTP и L2TP — они только на Android.

### Сборка

```bash
gradle :desktop:classicDist            # все четыре архива в desktop/build/classic/dist/
gradle :desktop:classicDistWindowsX86  # один
gradle :desktop:runClassic             # запуск из исходников
```

Собирается на любой ОС (jpackage не нужен): Gradle скачивает ядра и JRE и сверяет SHA-256. В Windows-архив входит
Temurin 11 JRE (32 или 64 бита), в Linux-архиве нужна системная Java 11+ (`sudo apt install default-jre`).

| Архив | sing-box | Xray | olcRTC | OpenFlux |
|---|---|---|---|---|
| windows-x86 | 386 `legacy-windows-7` | `win7-32` | — | — |
| windows-x64 | amd64 `legacy-windows-7` | `win7-64` | — | — |
| linux-x86 | 386 | `linux-32` | собран из исходников (GOARCH=386) | — (у апстрима нет 32-бит Intel) |
| linux-armv7 | armv7 | `linux-arm32-v7a` | собран из исходников (GOARM=7) | `openflux-linux-arm` |

Запуск: Windows — `Hydra.vbs` (двойной щелчок; без окна консоли), Linux — `./hydra.sh`.

## Android

- `x86` добавлен в `splits.abi`. `libbox.aar` (gomobile) и `libXray.aar` собираются под `android/386`
  (`gomobile bind -target android/arm64,android/arm,android/amd64,android/386`); AmneziaWG, olcRTC и OpenFlux —
  скриптами `scripts/build-*.sh` (в каждый добавлен `x86`: `GOARCH=386`, `i686-linux-android26-clang`).
- `scripts/release.sh` теперь требует четыре full-APK и проверяет, что в каждом есть ядро своей архитектуры.
- Самообновление выбирает файл по `Build.SUPPORTED_ABIS`; `x86` не путается с `x86_64`.

### Android TV / Google TV

Уже было: ярлык `LEANBACK_LAUNCHER`, баннер, `touchscreen`/`camera` не обязательны, навигация колонкой слева на широких
экранах, рамка фокуса на элементах для пульта. В 0.7.5 добавлено: на приставках нет ни `DocumentsUI`, ни фото-пикера,
ни камеры, и вызов выбора файла (резервная копия, журнал, фото с QR) или сканера QR раньше мог закрыть приложение
исключением. Теперь вместо падения — подсказка «скопируйте ссылку и вставьте из буфера». Добавить сервер на ТВ можно
через «Вставить из буфера» или подписку.

Не проверено на настоящем телевизоре и на образе Android TV (в среде проверки нет TV-образа): только сборка и
проверка кода. Пожалуйста, проверьте: запуск из лаунчера, навигацию пультом по всем вкладкам, ввод адреса
подписки экранной клавиатурой, подключение.

### Почему не Android 5–7

`minSdk` остаётся 26. Опускание до 21 даёт 64 ошибки API (проверено линтом): `TileService` (24), `KeyGenParameterSpec`
(23), `Service.stopForeground(int)` (24), `PendingIntent.getForegroundService` (26), `java.util.Base64` (26) и др. Все они
обходятся (`@RequiresApi`/ветки по `SDK_INT`/`android.util.Base64`), но без эмулятора Android 5–7 проверить
работу VPN-службы и ядер нельзя, а выпускать непроверенное в VPN-клиенте нельзя. Это отдельная работа.

## Windows XP SP3 — почему невозможно и что делать

Прямой путь закрыт, причины независимые (каждой достаточно):

1. **Ядра sing-box и Xray написаны на Go.** Go 1.21+ требует Windows 10 / Server 2016; Go 1.20 был последним для
   Windows 7/8; XP и Vista Go перестал поддерживать ещё раньше. Для Windows 7 существуют особые «legacy»-сборки
   с патченым Go — для XP их нет.
2. **Java.** Последняя Java для XP — 7 (2015). Hydra Classic требует 11.
3. **TLS.** Системная криптография XP (SChannel) не умеет TLS 1.2, а протоколы Hydra (REALITY, современные VLESS/Trojan)
   требуют TLS 1.3 и современных наборов шифров; подписки и обновления идут по HTTPS с современными сертификатами.

Новый клиент «с нуля» под XP (C++ на тулсете `v141_xp` с собственным TLS 1.3) теоретически возможен, но это отдельный
проект со своей безопасностью, а не доработка Hydra, и в 0.7.5 не делается.

**Обходные пути (работают сегодня):**

1. **VPN на роутере** — лучший вариант: весь компьютер с XP за роутером с Hydra for Router (его настраивает
   вкладка «Роутеры»). На XP ничего ставить не нужно.
2. **Прокси в локальной сети.** На другом устройстве (ПК с Hydra, телефон) включите «Раздача VPN в локальную сеть»
   (Настройки → хотспот-прокси на Android, «Раздача VPN в локальную сеть» на ПК): получится HTTP/SOCKS5-прокси с логином
   и паролем. На XP укажите его в браузере, который ещё поддерживает XP (Firefox ESR 52, Opera 36, Chrome 49) или
   для всей системы — скриптом `docs/legacy/xp-proxy.cmd` (настройки Internet Explorer/WinInet). Для программ,
   не знающих про прокси, подойдёт Proxifier 3.x или SocksCap.
3. **Штатные VPN Windows XP.** XP умеет PPTP и L2TP/IPsec (SSTP — с Vista). Если у вашей панели есть такой сервер
   (Android-версия Hydra как клиент умеет PPTP/L2TP/SSTP), XP подключается мастером «Новое подключение». Предупреждение:
   PPTP с MS-CHAPv2 криптографически сломан, годится только когда нет другого варианта.
4. **Виртуальная машина.** XP внутри VirtualBox/VMware на современном ПК с Hydra: в режиме TUN через туннель идёт и
   трафик гостя (NAT виртуальной машины — обычный трафик хоста).
