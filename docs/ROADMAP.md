## Правила (решения владельца)

- **Не ломать сделанное.** Если новое ломает существующее — это чинится в том же выпуске, всегда. Цель — стабильно работающий
  продукт (14.10.2026).
- **Пре-релизы, пока владелец не проверил сам.** До его проверки всё выходит как `-a` / `-b` / `-rcN`.
- Каждая версия — релиз всех платформ одним конвейером (`scripts/release.sh`); в CHANGELOG честно пишется, что проверено и где.
- Общий код Android и ПК — `shared/`; iOS — порт на Swift (`ios/Packages/HydraKit`).

## Схема версий (решение владельца 12.10.2026)

`X.Y.Z`: **X** — основная полноценная версия; **Y** — фичи, идеи, промежуточные исправления; **Z** — мелкие исправления или
большая идея по шагам.

| Версия | Что это | Как публикуется |
|---|---|---|
| `X.Y.Z` | обычный релиз | релиз GitHub «последний», приложения предлагают обновление |
| `X.Y.Z-a` (`-a2`…) | **альфа** — непроверенный код, для тестирования | pre-release; ветка не вливается в `master`, пока не проверена |
| `X.Y.Z-b` (`-b2`…) | **бета** | pre-release |
| `X.Y.Z-rcN` | **кандидат в релиз** — почти готово, нужна неглубокая проверка | pre-release; после проверки выходит как `X.Y.Z` |

Порядок: `-a` < `-b` < `-rcN` < выпуск. Пре-релиз не становится «последним» на GitHub. Что предлагает приложение, решает
**«Участвовать в бета-тестировании»** (с 0.8.0): выключено — только выпуски; уровень «Релиз-кандидаты» — ещё и `-rcN`; уровень
«Разработчик» — ещё и `-a`, `-b` (до 0.8.0 переключателя не было: стоящему на пре-релизе приложение предлагало следующий
пре-релиз или выпуск с тем же номером). Пакеты ПК кодируют пре-релиз в третье число (`0.8.3-a` → `0.8.310`,
`0.8.3-b` → `0.8.330`), чтобы установщик видел возрастающую версию.
`versionCode` Android растёт сквозь ветки: 0.8.1-a = 66, 0.8.0-rc4 = 67, 0.8.1-b = 68, 0.8.0 = 69, 0.8.1-rc1 = 70, 0.8.1-rc2 = 71, 0.8.1 = 72, 0.8.2-a = 73, 0.8.2-a2 = 74, 0.8.2-a3 = 75, 0.8.2-a4 = 76, 0.8.2-b = 77, 0.8.2-rc1 = 78, 0.8.2-rc2 = 79, 0.8.3-a = 82, 0.8.3-b = 83, 0.8.3-b2 = 84.

### Очередь без номера

- **Аренда доменов третьего уровня для своих серверов** (запрос владельца 15.10.2026). Свой домен даёт то, чего нет у голого IP:
  обычный сертификат, маскировку Reality **self-steal** (Reality ведёт на свой сайт на том же сервере — SNI совпадает с сетью сервера)
  и XHTTP/gRPC за CDN, когда IP сервера уже заблокирован. Идея: сервис выдаёт имя вида `<имя>.<наш-домен>` на время (неделя, месяц),
  сам ведёт DNS-записи (A/AAAA на IP сервера пользователя) и продлевает; **оплата — через Telegram-бота «Радар»** (тот же аккаунт, что уже
  связан с Hydra: вход по коду, забор подписок). В приложении: при установке панели/сервера Hydra **сама предлагает** взять домен
  («подключение надёжнее с доменом») и после оплаты подставляет его — сертификат на домен, self-steal, адрес панели и подписки.
  Что нужно продумать: регистратор и зона (свой домен второго уровня, API DNS — Cloudflare/deSEC/свой PowerDNS), защита от злоупотреблений
  (фишинг на наших поддоменах → блокировка всей зоны), сроки и продление, что происходит с подключением по истечении аренды
  (предупреждение заранее, откат на IP), юридическая сторона (кто владелец зоны). Отдельный сервис + доработки бота «Радар»; в Hydra —
  экран «Домен для сервера».

- **Боковой проект: переезд между панелями** (запрос владельца 14.10.2026). Скрипт/утилита, которая переносит пользователей (UUID,
  пароли, лимиты, сроки, подписки) из базы одной панели в другую: 3x-ui ↔ x-ui ↔ s-ui ↔ Marzban/PasarGuard/Remnawave. Hydra уже
  сохраняет базу перед удалением (`/root/hydra-backups`), так что исходные данные есть. Начать с разведки готовых решений (у апстримов
  есть частичные миграции, напр. Marzban → PasarGuard), затем — свой конвертер со схемами баз и тестами на живых базах.
- **OpenFlux как выход для любых протоколов** (запрос владельца 14.10.2026): узел OpenFlux работает как VPN-сервер (проверено в 0.8.1-b
  на ПК и Android); использовать его выходом для других протоколов можно уже сейчас — «Маршрутизация» → правило/группа/цепочка
  «→ узел OpenFlux» (0.7.13). Дальше: цепочки «AmneziaWG/VLESS поверх OpenFlux» в один клик из карточки сервера и проверка на живых
  транспортах (Яндекс, Mail.ru).

- **Windows: ложное срабатывание антивируса** (Kaspersky `PDM:Trojan.Win32.Generic` с 0.7.20): подпись кода, отказ от скрытого
  PowerShell (страж прокси, перезапуск от администратора) и от самозамены при обновлении — план [`versions/0.7.21.md`](versions/0.7.21.md).
- **AmneziaWG-подключение на ПК** (сейчас на ПК сервер AmneziaWG ставится и обслуживается, но подключаться к нему — с телефона):
  движок-подпроцесс AmneziaWG → SOCKS5 (как OpenFlux/olcRTC) или wintun на Windows.
- **«Трафик Hydra через VPN» для AmneziaWG**: нужен `protect()` сокетов amneziawg-go до первого пакета и после смены сети (колбэк из Go).
- Отложено до тестового сервера: MS-SSTP по спецификации, SSTP/L2TP на живом сервере, IP/домен split для AWG и SSTP/L2TP.
- Проверки на живых сервисах: TG WS на телефоне и iOS, SmartCaptcha OpenFlux (нужен IPC-клиент ядра), перебор стратегий DPI у провайдеров РФ.
- Из ревизий 0.7.17–0.7.19: ACL каталога конфигов при запуске от администратора, kill switch в TUN на ПК, сведение дублей `app/` и `shared/`
  (в rc4 найдено, что `LinkParser`/`WireGuardParser`/`WireGuardConfigBuilder` в двух копиях расходятся — правки приходится делать дважды).
- Скриншоты README под 0.7.14–0.8.x.

## Принципы безопасности для своих серверов и панелей

Только серверы пользователя и только по его явной команде; команды показываются до запуска; скрипты апстрима — закреплённых
версий с проверкой SHA-256; ничего не открывается наружу без согласия; пароли, ключи и токены не пишутся в журнал и хранятся только
зашифрованными; при ошибке — остановка с понятной причиной.
