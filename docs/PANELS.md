# Совместимость с панелями

Hydra потребляет **стандартный формат подписки**, который отдают все четыре
панели: тело ответа — это либо plain-список ссылок (`vless://…`, по одной на
строку), либо тот же список в **base64**. `LinkParser.parseSubscription`
автоматически определяет base64 и раскодирует.

Многие панели меняют формат ответа в зависимости от заголовка **User-Agent**
или суффикса пути (`/v2ray`, `/clash`, `/sing-box`, `/json`). С 0.6.21 Hydra представляется
как Happ / INCY, но своим именем, и ожидает v2ray-формат (base64/plain):

```
User-Agent: Hydra/<версия>/android Dalvik/2.1.0 (Linux; U; Android <версия>; <модель>)
x-hwid: <UUID>            # аппаратный ID, показан в Профиле; нужен панелям с лимитом устройств
x-device-os: Android
x-ver-os: <версия Android>
x-device-model: <производитель модель>
```

Из ответа читаются заголовки `profile-title` (в т.ч. `base64:…`) — название подписки в списке,
`subscription-userinfo` — трафик и срок, `profile-update-interval` — период автообновления,
`support-url`. HWID — хеш ANDROID_ID + имени пакета (`HydraDevice`), не раскрывает исходный ID.

> Форматы описаны по состоянию на начало 2026 г. Панели активно развиваются —
> при расхождении сверяйтесь с их актуальной документацией.

## x-ui / 3x-ui (MHSanaei/3x-ui)

- Подписка включается в настройках панели (Subscription) и в клиенте инбаунда
  (по `subId`/email).
- URL вида:
  ```
  http(s)://<host>:<subPort>/<subPath>/<subId>
  ```
  Ответ — **base64** со списком `vless:// / vmess:// / trojan://` по всем
  инбаундам, привязанным к клиенту.
- JSON-вариант (для клиентов, понимающих xray json):
  ```
  http(s)://<host>:<subPort>/json/<subId>
  ```
- Hydra: используйте обычный (base64) URL — он разбирается «из коробки».
- **Ноды 3x-ui (0.8.2-a4):** нода — другая панель 3x-ui (v3.10+). Hydra ставит её на второй сервер, выпускает на ней токен
  с областью `node-sync` (`x-ui setting -getApiToken -tokenScope node-sync`), регистрирует в главной (`POST /panel/api/nodes/add`,
  порт панели ноды открыт только для главного сервера) и создаёт инбаунд с `nodeId` — главная панель передаёт его ноде, ссылки
  указывают на адрес ноды.

## PasarGuard

- Развитие ветки Marzban; поддерживает мультиформатную подписку.
- URL вида:
  ```
  https://<domain>/sub/<token>
  ```
- Формат определяется по **User-Agent** или query/пути. Типичные форматы:
  `v2ray` (base64), `clash`, `clash-meta`, `sing-box`, `outline`.
- **Установка из Hydra (0.8.2-a3):** «Мои серверы» → «Установить PasarGuard» — панель и нода в Docker, сайт только через
  туннель Hydra (`/dashboard/`), «Создать подключение» — VLESS/Trojan + REALITY, VMess; пользователь `hydra`.
- **Ноды (0.8.2-a4):** «Ноды» → «Добавить ноду» — на второй сервер ставится `pg-node` (сертификат и на адрес ноды,
  `--san-entries`), нода регистрируется в панели (`POST /api/node`, порты 62050–62051 только для главного сервера), к подключениям
  Hydra добавляются хосты с адресом ноды.
- Hydra: базовый `v2ray`-формат разбирается парсером. Формат `sing-box`
  (готовый JSON) можно скармливать напрямую движку sing-box в обход парсера
  (расширение на будущее — см. TODO в `SingBoxConfigBuilder`).

## Remnawave

- Современная панель; подписка отдаётся по короткому идентификатору:
  ```
  https://<sub-domain>/<shortUuid>
  ```
  (в некоторых конфигурациях — `/api/sub/<shortUuid>`).
- Мультиформат: `v2ray`/`xray` (base64), `sing-box`, `clash`/`mihomo`,
  выбор — по **User-Agent** либо суффиксу пути (`/sing-box`, `/clash`, `/json`).
- Есть система шаблонов и «subscription page» (HTML). Для клиента используйте
  «сырой» формат (не HTML-страницу).
- **Установка из Hydra (0.8.2-a3):** «Мои серверы» → «Установить Remnawave» — панель, база, кэш, нода и прокси Caddy на
  127.0.0.1 (панель требует «обратный прокси + HTTPS»), сайт только через туннель Hydra; «Создать подключение» — VLESS/Trojan +
  REALITY (VMess панель не принимает); пользователь `hydra`, отряд `Hydra`.
- **Ноды (0.8.2-a4):** на второй сервер — `remnawave/node` с ключом главной панели (`/api/keygen`), `POST /api/nodes` со всеми
  инбаундами профиля (порт 2222 только для главного сервера), хосты подключений Hydra с адресом ноды.
- Hydra: v2ray-формат — «из коробки»; для нативного sing-box-конфига
  добавьте обработку JSON-ответа.

## Рекомендации по интеграции

1. В диалоге «Импорт» вставьте URL подписки — Hydra скачает и разберёт её,
   создаст записи серверов, привязанные к `Subscription.id`.
2. Для панелей с UA-зависимым форматом при необходимости меняйте
   `Subscription.userAgent` (например, на `v2rayNG`, `sing-box`, `clash`),
   чтобы получить нужный формат.
3. Обновление подписки удаляет старые серверы этой подписки и подставляет новые
   (`ServerRepository.refreshSubscription`).

## Связь с UniSub Bot

Если вы агрегируете панели через собственный сервис (единая подписка,
объединяющая x-ui/3x-ui/PasarGuard/Remnawave), Hydra'у достаточно **одного**
итогового URL этой агрегированной подписки — он получит уже объединённый список
серверов.
