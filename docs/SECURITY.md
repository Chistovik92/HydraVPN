# Политика безопасности

## Сообщить об уязвимости

- **Приватно:** создайте security advisory на GitHub
  (Security → Report a vulnerability) — рекомендуемый путь.
- **Быстро:** Telegram-контакт проекта (см. README).
- Не публикуйте детали эксплуатации в публичных issues до исправления.

Ожидаемый срок ответа — 7 дней. Просьба приложить: версию приложения,
протокол/движок, шаги воспроизведения или PoC.

## Модель угроз (кратко)

- **Клиент доверяет серверу профиля.** Секреты профилей хранятся в Room
  открытым текстом — до продакшена запланирован Keystore
  (docs/ARCHITECTURE.md, «Что доработать»).
- **SSTP:** проверка сертификата сервера включена по умолчанию.
  `sstp://…?allow_insecure=1` отключает проверку (а также сверку хэша из
  ENC_INFO) — только для тестовых серверов. Crypto-binding (MS-CHAPv2 +
  Compound MAC) защищает от «расщепления» TLS-канала и аутентификации.
- **L2TP:** без IPsec данные PPP не шифруются (MS-CHAPv2 защищает только
  пароль). Мы сообщаем об этом в UI/доках; для приватного канала —
  SSTP/WireGuard.
- **PAP** передаёт пароль открыто внутри туннеля (SSTP-TLS или L2TP без ESP) —
  используйте MS-CHAPv2 везде, где сервер позволяет.
- **Beta-движки (WDTT/olcRTC):** не включайте для чувствительного трафика,
  пока интеграция не вышла из BETA.
- **Логи** хранятся только в памяти сессии (экран «Логи», последние 500 строк),
  на диск не пишутся и никуда не отправляются.

## Чего мы принципиально не делаем

- Не собираем телеметрию и не отправляем метрики.
- Не встраиваем бинарники сторонних проектов без проверки лицензий
  (THIRD_PARTY_NOTICES.md).
- Не заявляем поддержку протоколов, невозможных на Android без root
  (PPTP — честный отказ вместо полусвязности).

## Зависимости

Известные уязвимости зависимостей отслеживаются через Dependabot
(включён на GitHub). Критичные для нативных ядер (sing-box/Xray/AWG)
обновляются пересборкой `.aar` — см. docs/BUILD.md.
