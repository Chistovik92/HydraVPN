# Политика безопасности

Пересмотрено в 0.6.23 (Фаза 8).

## Сообщить об уязвимости

- **Приватно:** создайте security advisory на GitHub
  (Security → Report a vulnerability) — рекомендуемый путь.
- **Быстро:** Telegram-контакт проекта (см. README).
- Не публикуйте детали эксплуатации в публичных issues до исправления.

Ожидаемый срок ответа — 7 дней. Просьба приложить: версию приложения,
протокол/движок, шаги воспроизведения или PoC.

## Модель угроз

### Данные на устройстве

- **Секреты профилей** (UUID, пароли, ключи Reality/WireGuard, токены подписок)
  хранятся в Room **открытым текстом** в приватном каталоге приложения. От других
  приложений их защищает песочница Android, от root/физического извлечения — нет.
  Шифрование через Android Keystore по-прежнему в планах (docs/ARCHITECTURE.md).
- **`android:allowBackup="false"`** — система не уносит базу и настройки в облачную
  резервную копию Google и не отдаёт их через `adb backup`.
- **Резервная копия Hydra** (Настройки → Резервная копия) — JSON с секретами в открытом
  виде. Так и написано в UI: хранить как пароль.
- **Логи.** Режим по умолчанию — «только ошибки и предупреждения», без адресов сайтов.
  Режим «полный журнал» пишет адрес каждого соединения на диск (история посещений) —
  UI предупреждает об этом. Срок хранения 1/3/7 дней. Никуда не отправляются.

### Экран и посторонние глаза (Фаза 8)

- **Скрывать ключи** (по умолчанию включено): на экране ссылки показываются без UUID,
  паролей, ключей Reality и токенов (`SecretMask`), пароль хотспота — точками.
  QR, копирование и «Поделиться» отдают полную ссылку: это защита от взгляда через
  плечо и скриншота, а не от владельца.
- **Блокировка приложения** (по умолчанию выключена, Android 9+): отпечаток, лицо или
  PIN экрана через системный BiometricPrompt при открытии и после 30 с в фоне. Пока
  блокировка включена, окно помечено `FLAG_SECURE` — не попадает в скриншоты, запись
  экрана и превью «Недавних». VPN при этом продолжает работать: блокировка закрывает
  интерфейс, а не туннель. Если на устройстве убрали и отпечатки, и PIN, приложение
  пускает без проверки и пишет об этом в журнал — чтобы владелец не оказался заперт.
- Плитка в шторке и виджет показывают **локацию** подключения (флаг, страна, имя
  сервера) — на заблокированном экране её может увидеть посторонний. Секретов там нет.

### Сеть

- **Собственный трафик Hydra идёт мимо туннеля** (`addDisallowedApplication(packageName)`),
  иначе ядро не смогло бы достучаться до прокси-сервера. Это касается запросов самого
  приложения: загрузки подписок (с HWID в заголовке) и проверки обновлений. Провайдер
  видит, что вы обращаетесь к панели подписки и к api.github.com.
- **Проверка обновлений** (Фаза 8, по умолчанию включена, выключается в «О приложении»):
  раз в сутки GET `api.github.com/repos/Chistovik92/HydraVPN/releases/latest`. APK
  приложение само не скачивает и не ставит — нет `REQUEST_INSTALL_PACKAGES`.
- **HWID** — стабильный идентификатор устройства в заголовке `x-hwid` к панели подписки;
  нужен панелям с лимитом устройств. Отправляется только на адреса подписок пользователя.
- **IPv6** (Фаза 8): по умолчанию режим «Блокировать» — маршрут `::/0` уходит в tun без
  IPv6-адреса, поэтому IPv6 не утекает мимо VPN. Режим «Через туннель» даёт tun ULA-адрес.
- **DNS**: по умолчанию DoH внутри туннеля; пресет «Системный резолвер» — явно помечен
  как идущий мимо туннеля. Проверка утечек — через браузер (из приложения невозможна
  по той же причине: Hydra вне туннеля).
- **Хотспот-прокси** слушает `0.0.0.0` с обязательными логином и паролем (≥ 6 символов).
  Любой в той же сети, кто знает пароль, пользуется вашим VPN — в UI есть предупреждение.
- **Kill Switch** держит tun «чёрной дырой» при ошибке/обрыве; от отзыва VPN системой
  (другое VPN-приложение) защищает только системный Always-on + «Блокировать соединения
  без VPN». Hydra показывает, включён ли он (статус из работающего сервиса, Android 10+).

### Протоколы

- **SSTP:** проверка сертификата сервера включена по умолчанию.
  `sstp://…?allow_insecure=1` отключает проверку (и сверку хэша из ENC_INFO) — только
  для тестовых серверов. Crypto-binding (MS-CHAPv2 + Compound MAC) защищает от
  «расщепления» TLS-канала и аутентификации.
- **L2TP:** без IPsec данные PPP не шифруются (MS-CHAPv2 защищает только пароль).
  Об этом сказано в UI/доках; для приватного канала — SSTP/WireGuard.
- **PAP** передаёт пароль открыто внутри туннеля — используйте MS-CHAPv2, где сервер позволяет.
- **Beta-движки (olcRTC, OpenFlux):** не включайте для чувствительного трафика, пока не
  вышли из BETA. WDTT не интегрирован (docs/ECOSYSTEM.md).

## Чего мы принципиально не делаем

- Не собираем телеметрию и не отправляем метрики; в приложении нет рекламы и трекеров.
- Не встраиваем бинарники сторонних проектов без проверки лицензий
  (THIRD_PARTY_NOTICES.md).
- Не заявляем поддержку протоколов, невозможных на Android без root
  (PPTP — честный отказ вместо полусвязности).
- Не устанавливаем обновления сами и не просим права на установку пакетов.

## Зависимости

Известные уязвимости зависимостей отслеживаются через Dependabot
(включён на GitHub). Критичные для нативных ядер (sing-box/Xray/AWG)
обновляются пересборкой `.aar` — см. docs/BUILD.md. CI (Фаза 8) собирает
`libbox.aar` из исходников sing-box заданной версии и проверяет, что ядро внутри APK.
