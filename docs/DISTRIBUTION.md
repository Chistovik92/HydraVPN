# Распространение

Основной канал — **GitHub Releases** (`scripts/release.sh`): два APK, `Hydra-full-*.apk`
(рабочий, с ядрами) и `Hydra-stub-*.apk` (симуляция, для разработки). Приложение само
проверяет последний релиз раз в сутки (Настройки → О приложении) и открывает страницу
релиза — устанавливает пользователь.

## F-Droid

Подготовлено в 0.6.23:

- `fastlane/metadata/android/{en-US,ru-RU}/` — название, краткое и полное описание,
  скриншоты (`en-US/images/phoneScreenshots`), история изменений по `versionCode`
  (`changelogs/36.txt` — 0.6.23; `57.txt` — 0.7.14–0.7.15; `58.txt` — 0.7.16; `59.txt` — 0.7.17; `60.txt` — 0.7.18; `61.txt` — 0.7.19; `62.txt` — 0.7.20; для следующих релизов добавляйте файл с их `versionCode`, до 500 знаков). F-Droid читает эту структуру прямо из репозитория.
- Нет трекеров, рекламы и проприетарных библиотек (ZXing, OkHttp, AndroidX — открытые).

Что остаётся владельцу:

1. **Сборка из исходников.** F-Droid собирает APK сам и не принимает готовые `.aar`.
   Рецепт (`metadata/ru.gidravpn.hydra.yml` в репозитории fdroiddata) должен собирать
   `libbox.aar` из sing-box той же версии — команды есть в `.github/workflows/android.yml`
   (job `build-native`) и docs/BUILD.md 2.1. Xray, AmneziaWG, olcRTC, OpenFlux — так же,
   скриптами из `scripts/`, либо full-сборка F-Droid идёт без них (протоколы честно
   откажут при подключении).
2. **Подпись.** F-Droid подписывает своим ключом — это другое приложение для системы,
   обновление поверх GitHub-версии невозможно без переустановки. Альтернатива —
   reproducible builds с подписью разработчика.
3. Открыть merge request в https://gitlab.com/fdroid/fdroiddata.

## RuStore

Нужен аккаунт разработчика RuStore (владелец). Загружается `Hydra-full-<версия>-arm64-v8a.apk` (с 0.7.2 — по файлу на архитектуру; для RuStore нужны arm64-v8a и armeabi-v7a),
подписанный релизным ключом (`keystore.properties`), — обновления совместимы с
GitHub-версией. Описание и скриншоты — те же файлы из `fastlane/metadata/android/ru-RU`.
VPN-приложения проходят ручную модерацию; в карточке стоит прямо указать, что сервис
серверов не продаёт.

## Google Play

Не планируется: политика Play для VPN (VpnService) требует объяснения назначения и часто
блокирует клиенты обхода блокировок; кроме того, релизная подпись Play App Signing
несовместима с текущими установками.
